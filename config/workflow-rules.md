# 工作流与选择规则

| 任务 | 最短合理路径 |
|---|---|
| 从零/从文档制作 | 理解目标 → 内容策划确认 → 视觉样张确认 → 完整预览确认 → 正式生成 → QA → 演讲稿/归档 |
| 内容已完整 | 校对内容边界 → 视觉探索 → 预览确认 → 生成和 QA |
| 已有模板 | 原稿备份 → 检查母版/字体/占位符 → 内容映射确认 → 编辑副本 → 渲染回归 |
| 修改现有 PPT | 锁定页码和保护对象 → 最小编辑 → 比较修改页及未修改页 |
| 只要 HTML | 内容和视觉确认 → HTML → 浏览器导航/演讲模式 QA → 归档 |
| HTML 转可编辑 PPT | 固定确认稿 → 提取内容/画布/布局/字体/颜色 → 原生对象重建 → 对照渲染 → 披露差异 |
| 只要演讲稿 | 读取确认版 PPT → 按页备注和时间预算 → 用户确认稿件 |

HTML 是视觉预览格式，PPTX 是另一种对象模型；两者共用内容与设计参数，不承诺 CSS/动效逐像素自动转换。

PptxGenJS 适合从零构建文字、图表和原生形状；ppt-master 适合其受支持 SVG → DrawingML 工作流、模板和现有文稿编辑。先读取上游路由、依赖和完整性检查；保留其专用工作区结构。内置 Presentations 为可选独立引擎，不要求旧 openai/skills/.curated/slides 路径。

HTML 风格探索优先 frontend-slides；归藏适用于其 A/B 风格及演讲者呈现，不承担 PPTX 转换。ui-ux-pro-max 只提取适用于演示的字体、色彩、间距、层级知识，不强加网页导航、表单或手机布局。

QA 的问题包含页码、位置、严重度、证据、建议、处理状态。P0/P1 阻断交付；P2 明确处理或由用户接受。保留生成源代码、源数据、最终文件、预览、演讲稿、来源和 QA，不将未检查标成通过。
